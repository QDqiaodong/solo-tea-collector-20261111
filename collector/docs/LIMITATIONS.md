# 限制与边界说明

## 1. 不提供服务端同一时刻的一致性快照

现有三个列表接口是独立的全量查询，**没有**分页、增量游标、删除日志或
服务端快照隔离。本工具按顺序分别抓取三个资源，抓取窗口内源端若发生
并发写入（新增/修改/删除），三个资源反映的可能不是同一瞬间的状态。

工具**只保证本地发布的原子性**：本地可见版本要么完全是上一版、要么完全是
本次三资源解析后的新版，不存在"半个新版本"。跨资源的引用完整性在本地
通过 accepted 集合内的外键闭合校验 + 级联隔离兜底（例如抓取窗口内某农户
被删除，引用它的地块/收购单会进入隔离区并在审计中可查），但无法消除
抓取窗口本身的时间差。如需服务端时点一致性，需要后端新增快照/版本接口，
不在本工具范围内。

## 2. 全量采集模型

接口无分页与增量能力，工具每次运行全量拉取三个资源。数据量增长到单次
响应明显大于 HTTP/存储承受范围时，需要后端先提供分页或增量协议；
当前实体规模（村级加工厂台账）下全量模式简单且可验证。

## 3. 并发范围

- 互斥针对**同一个 SQLite 文件**：通过 `collector_lock` 咨询锁 + WAL +
  `BEGIN IMMEDIATE` 保证同一目标库同一时刻只有一个采集进程能发布；
  锁等待有界（默认 30s），超时以退出码 4 明确退出，不会损坏已发布数据。
- 不同数据库文件之间互不影响；查询/导出命令是只读连接，可与采集并发执行。
- 咨询锁依赖心跳 TTL 兜底进程崩溃：若机器时钟大幅跳变，TTL 判断可能提前
  或延后；正常 NTP 校时环境下无影响。

## 4. 时区与日期

- 后端 Jackson 配置时区 Asia/Shanghai 且以 ISO-8601 字符串输出，工具按
  原始字符串存储，不做时区换算；`purchaseDate` 按业务日（yyyy-MM-dd）汇总。
- 工具内部审计时间戳使用 UTC 并带 `Z` 后缀，与业务日期列区分。

## 5. 十进制精度

- 抓取时 JSON 数字以字符串接收（`parse_float=str`），Decimal 字段全程
  不经过 float；SQLite 以 TEXT 保存，按日聚合时转 Decimal 精确求和。
- 标度按源值保留（如 `12.50000000` 原样保存）；若后端未来改变序列化方式
  （例如输出科学计数法），Decimal 仍可解析，但建议保持定点小数字面量。

## 6. 安全边界

- 工具不持久化任何认证信息；凭据只存在于进程内存的请求头中，日志对
  URL 内嵌凭据、敏感查询参数与认证头统一脱敏。
- SQLite 文件本身不加密；文件级权限、磁盘加密由部署环境负责。
- 工具只对三个 GET 列表接口发起请求，不会向后端写入任何数据。

## 7. 运行环境

- Python 3.11+，仅标准库；Windows/macOS/Linux 均可运行（信号处理在不支持
  的平台自动降级）。
- 网络协议支持 http/https；自签名证书的信任策略沿用 Python 默认 CA 库，
  本工具不提供关闭证书校验的开关。
